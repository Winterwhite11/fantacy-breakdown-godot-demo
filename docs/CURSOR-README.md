## 1. 这个项目是什么

**《Fantacy Breakdown》** —— 咏唱制卡牌 + 搜打撤（extraction）游戏。

- **核心机制**：基本「字」（元素）组合成复杂「字词」。咏唱时间 = 堆叠字数。
- **数值**：1s=5伤 / 2s=12 / 3s=21 / 4s=32 / 5s=45 / 6s=60；护甲只存 5s；前后摇 0.5+1.5。
- **铭文耐性**：决定一个复杂字最多堆几个基本字。豪杰=6，其余=5。
- **三大流派**：合成流（基本） / 环境流 / 召唤流。
- **结算节奏**：敌人每 5s 行动一次，状态每 5s 结算一次，玩家每 5s 约出 1 张牌。

### 2.1 修复了一个真实的数据缺陷（很重要）

旧解析器的正则识别不了 `砂+火/加热+增幅` 这种**斜杠二选一配方**，导致：

| | 修复前 | 修复后 |
| --- | ---: | ---: |
| 有配方的 specials | 64 / 75 | **65 / 71** |
| 无配方 | 11 | **6**（召唤流核心卡，原文即无配方） |
| 钢铁配方 | **无** | `sand+fire+amp` |
| 电获取路径 | **无** | `sand+amp` |

**这解释了为什么 demo 里钢铁像个"凭空得来的超模牌"** —— 它的配方链在代码里根本不存在。

### 2.2 敌人档位错标的根因

用户设计文档给每场遭遇都标了档位（`对标75血一回合12伤害 ——2档`）。Cursor 把**难度档位当成了奖励档位**用，于是：

| 遭遇 | 设计档 | 旧代码 | 现已修正 |
| --- | ---: | ---: | ---: |
| ENC-01 四个野人 | 2 | 3 | **2** |
| ENC-03 损坏的机器人 | 2 | 3 | **2** |
| ENC-10 冰与火 | **4（精英）** | 3 | **4** |

现在拆成两个字段：`tier`（难度，设计文档 1-5）+ `rewardTier`（奖励 1-3），
通过 `FBEncounters.rewardTierOf()` 取用。**以后改难度不会连带改掉落。**

### 2.3 定价公式（数学上已证明）

```
基础牌 P = 2.0 × (WV/5)^1.734        （锚点：WV5=2代币，WV32=50代币）
合成牌 P = max( Σ材料价 × (1 + 0.22×材料数), 按强度定价 )
```

- `WV`（窗口价值）把伤害/护甲/治疗/状态折算到统一的「一个 5 秒窗口」尺度。
- **为什么不取整**：取整会让 WV1 与 WV2 同价 → 性价比逆序 → 鼓励堆最便宜的牌。
  已证明取整**无法**同时满足「价格严格递增」与「性价比严格递减」。故保留小数，
  仅在 UI 用 `displayPrice()` 取整。

## 3. 自动化作业（本轮新增，请务必用）

### 统一价值口径（2026-10-13）

**问题**：材料在 8~80 量级，收集品在 40~38000 量级 —— 同一个经济里差三个数量级，
于是出现「一个白收集品 = 50 张基础牌」。

**现在只有一条价值阶梯**（`loot.js` 的 `RARITY_VALUE_STEP`），材料与收集品共用：

```
白 10 · 绿 22 · 绿+ 56 · 蓝 48 · 紫 105 · 金 230 · 唯一 500
```

- 收集品在其档位 ±40% 内随机；材料取阶梯上的固定点
- `green+`（56）是**为配方成本细分而加的**：22 → 48 跨度太大，
  没有这一档就无法让武器价格单调
- 收集品 `VALUE_RANGE` 从 40~38000 降到 **6~700**
- 代币因此成为主要收入：各档战金上调为 14~22 / 18~28 / 30~44
- 经济参数同步下调（战备成本 60/120/240），实测三条路线净值为正且比值 2.06x

> ⚠ 改收集品价值区间时，必须同步 `game-design-workflow/data/economy-config.json`
> 的 `collectibleValue`，否则 `npm run economy` 会给出错误结论。

### 战备定价是一条恒等式（不是拟合）

用战力（WV）定价、用材料阶梯算成本，是两条独立尺度，**必然互相矛盾** ——
两轮拟合都甩不掉 9~11 项「合成比直购还贵」（合金胸甲直购 204、材料 2960）。
现行规则：

```
有配方  →  P = 材料成本 × EQUIP_CRAFT_MARKUP(=2)
无配方  →  P = 战力曲线
```

于是「合成 = 直购的一半」**不可能被违反**（12/12 精确满足），
且价格自动锚定到统一材料阶梯。无配方的基础装备仍走战力曲线。

### 全部武器都有正式配方

6 把武器的材料成本随战力递增 —— 这是**同槽位价格单调**的前提。
已校验：不存在「更高 WV 却更便宜」，也不存在「实质受支配」
（明显更强 **且** 明显更便宜）的同槽位选项。

> ⚠ 「受支配」判据要求 **WV 高 5% 且价格低 10%**。只要求「WV 不低、价格不高」
> 会把**同级内功能不同**（爆发 vs 持续、不同 debuff）、强度仅差 2% 的组合
> 误判为受支配 —— 这是标定过程中踩过的坑。

### 战备系统（装备 / 合成 / 图标）

### 四类装备，共 15 件

| 槽位 | 机制 | 条目 |
| --- | --- | --- |
| 武器 | `hitInterval` 触发间隔 · `hitDamage` 单次伤害 · `hitDebuff` 附带状态 | 手枪 5/9s · 速射手枪 4/6s · 重铳 **14/17s**（爆发）· 淬毒弩 5/9s+中毒1 · 喷火铳 6/9s+燃烧2 · 霜刺枪 8/11s+冻结1 |
| 护甲 | `maxHpBonus` 最大生命 · `debuffResist` debuff 抗性 | 简易 +10 · 絮衬 +18(毒/燃-1) · 合金 +30(四抗各-1) |
| 头盔 | `startBlock` 开局护甲 · `damageReduction` 每次受伤减免 | 简易 3 · 护目 6+减免1 · 壁垒 10+减免3 |
| 背包 | `capacity` 收集品格数 | 2 / 5 / 9 |

**战斗接线**（`combat.js`）：
- 武器走既有 `_gearIntervals` 节拍，触发时附加 `hitDebuff`
- 头盔减免在 `_damagePlayer` 中**先于护甲结算**，但**至少留下 1 点穿透伤害** ——
  否则高减免会让低伤敌人完全无效，战斗变成无风险
- 护甲抗性并入既有 `_playerResists` 通道（`listPlayerResists(..., loadout)`）

> ⚠ **武器平衡要用「固定窗口总伤害」衡量，不要用「单次伤害 × DPS」**。
> 后者等于 `d²/interval`，会把单次伤害平方放大 —— 曾把一个健康的武器组
> 误判为 6.4x 失衡。当前 60s 总伤害落在 30~42（1.40x），单次伤害跨 4~14（3.5x），
> 即「爆发」是一条独立的强度轴，且无废牌。

### ⚠ 材料价值服从配方，不是服从稀有度

收集品稀有度区间（白 40~160 / 绿 180~480 / 蓝 520~980 / 紫 1400~2800）是**收藏品口径**，
而战备定价走**战力口径**，两者差一个数量级。按稀有度给材料定价会让合成**永远亏本**
（第一版实测：合金胸甲直购 204、材料 2960）。

**现行规则**（写在 `loot.js` MATERIALS 注释里）：

```
合成总成本 ≈ 直购价的 50%      ← 攒材料省钱，直接买省事
```

材料价值据此反推：纤维 8 · 合金板 14 · 火药 10 · 透镜 14 · 燃烬/毒囊 24 · 符石 80。
已校验 **11/11 项可合成战备的合成价低于直购价**。

### 战备定价（并入卡牌经济）

```
P = 293 × (min(WV, 60) / 32) ^ 1.413
```

`WV` 按「60s 一场的总产出」折算（武器含爆发加成），标定锚点取自材料成本：
合金胸甲 WV 51.5 → 690（= 合金板 120×2 + 封纹符石 450 的原始配方口径）。
**性价比随 WV 严格递减，0 处逆序。**

## 经济体系（2026-10-13 全面重构：千-万量级）

> **参照《三角洲行动》**：一套中档战备 ≈ 一次成功撤离的收入；跑刀低投低产、
> 猛攻高投高产；收集品是主要收入。

### ⚠ 四条口径必须分开，不要互相引用（本轮最大的坑）

| 口径 | 决定什么 | 量级 | 定义处 |
| --- | --- | --- | --- |
| **收集品价值阶梯** | 一局的**收益** | 3,500 ~ 200,000 | `loot.js` `RARITY_VALUE_STEP` / `VALUE_RANGE` |
| **材料价值** | **装备价位** | 250 ~ 8,240 | `loot.js` `MATERIALS` |
| **战斗代币** | 保底收入 | 4,000 ~ 20,000 /节点 | `loot.js` `TIER_GOLD` + `economy-config.json` |
| **装备定价曲线** | 无配方装备价 | `EQUIP_BASE` 9,000 | `economy.js` `EQUIP_COEF` |

**收集品价值与材料价值相差 5~10 倍是设计如此**。我曾让材料引用收集品阶梯
（`value: RARITY_VALUE_STEP.green`），结果阶梯一抬，材料成本翻倍，
中档四件套从 49k 涨到 91k、猛攻从 149k 涨到 295k，三条路线净值全部转负。
**`equip-test.mjs` 现在会断言材料定义块不引用 `RARITY_VALUE_STEP`。**

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 跑刀（档1） | 18,174 | 19,800 | 31,482 | **51,282** | 33,108 | 61% |
| 常规（档2） | 50,480 | 31,590 | 56,501 | **88,091** | 37,611 | 64% |
| 猛攻（档3） | 85,580 | 53,550 | 98,210 | **151,760** | 66,180 | 65% |

- 三条路线净值均为正，**比值 2.00x**（无单一路线支配）
- 收集品占 61~65%（此前只有 21~59%，即代币在唱主角——与「收集品是主角」矛盾）
- **ROI 递增的是跑刀**（236% / 100% / 105%）：跑刀效率最高、上限低；
  猛攻绝对值最高、波动最大。二者取舍成立。

### 两条标定工具（改经济参数前先用它）

```bash
npm run economy:calibrate   # 用当前参数测量，并对 T1~T4 目标逐条判定
npm run economy:solve       # 给定目标，反推「每节点收集品价值」与战备成本
npm run economy             # Monte Carlo（400 局/路线，固定种子可复现）
```

> ⚠ **战备成本必须从 `EQUIP_DEFS` + `equipPrice` 累加**（`economy-test.mjs` 已如此）。
> 若写死在 config 里，经济参数一改成本就与实际装备脱节 —— 本轮踩过这个坑。

### 配方是主题化的，不是「成本凑数」

`npm run recipes`（`tools/themed-equip-recipes.py`）

早期用「只盯成本」的生成器，产出了 `封纹符石 + 火药×52` 这种配方：
成本对，但要攒 52 件火药，语义也荒谬。现在约束为：

- 每件装备 **3~6 件材料**，主题化（金属 / 弹药 / 能量 / 化学 / 织物）
- 材料**单价**用阻尼最小二乘求解，使 Σ材料 仍精确落在目标成本上（最大偏差 22%）

> 二者由同一组目标成本驱动，不会脱节。

## 一键合成（战备合成台）

合成台每张战备卡有两个按钮：

| 按钮 | 行为 |
| --- | --- |
| **合成** | 材料已齐时直接合成（原有逻辑） |
| **一键合成** | 缺料时**自动从市场按最低价补齐**，确认后买入并合成 |

缺料时会显示「一键合成（补齐 12,800）」，并在卡片下方注明
「市场可补齐 N 件 · 需 X 代币」；市场缺货时按钮禁用并提示缺什么。

### 两个刻意的设计决定

1. **只买最低价，且不买自己的挂牌**
   自购只扣手续费（这条规则是为了让"垄断市场"可行），
   所以一键合成若能买自己的单，就变成了**印钞机**。故显式跳过 `sellerId === "local"` 的挂单。

2. **宁可不做，也不半买**
   市场供不上、或代币不足时**直接拒绝且不改动任何状态**。
   半买会让玩家拿到一堆他没要的材料。

> 为此市场新增了**常驻材料货架**：9 种材料各有稳定 `catalogId`
> （`material-<id>`），系统价 = 材料价值 × 1.35。没有这个，一键合成无从买起。

### 相关函数（`app.js`）

```js
quoteCraftFromMarket(defId)   // 只算不改：缺口 / 最低价 / 总花费（UI 预览与测试用）
craftEquipOneClick(defId)     // 执行：逐项买入最低价挂单 → 合成
```

拆成两个函数是为了**先报价再花钱**，也为了让整条路径能在无浏览器环境下测试
（`tools/oneclick-test.mjs`，27 项）。

> ⚠ `craftEquipOneClick` 读钱包时曾用 `window.FBSave?.loadVault?.() || { tokens: 0 }`，
> 在存档层缺失时会**静默退化成"永远余额不足"**。现在区分
> 「钱包不可用」与「代币不足」两种失败原因。

## 悬浮放大预览（`js/preview.js`）

鼠标在**卡牌 / 战备 / 收集品 / 材料**上停留 **1 秒**，弹出放大的信息面板展示其效果（仿杀戮尖塔）。

### 接入方式：事件委托，不要逐元素绑定

在 `document` 上统一监听，元素只要带两个属性就自动获得预览能力：

```html

<div data-pv="equip"    data-pv-id="shotgun_heavy">…</div>
<div data-pv="collect"  data-pv-json='{"name":"…","value":40}'>…</div>
<div data-pv="material" data-pv-json='{"name":"合金板","materialId":"alloy_plate"}'>…</div>
```

新增界面**只需加这两个属性**，无需改 preview.js。
`tagPreviewables()`（在 `app.js`）会在每次渲染后扫描已知的卡片类并自动打标，
已覆盖 **10 类元素**：卡牌仓库 / 合成台（战备+卡牌）/ 装备仓库 / 已装备槽位 /
收集品仓库 / 材料仓库 / 市场三个分区。

### 三个容易做错的点

1. **在子元素之间移动不能重置计时**。1 秒延迟靠 mouseover 判断「悬停元素是否变化」
   实现；若每次 mouseover 都重置，卡片内部的文字节点会让计时器永远不触发。
2. **`pointer-events: none`**。否则浮层会挡住拖拽（战备界面大量依赖拖动）。
3. **离开要收起**：scroll / blur / mousedown / Escape 都要 hide，否则浮层会残留在屏幕上。

> ⚠ 测试视口避让时，`place()` 依赖内部光标状态。若不在测试里**注入坐标**，
> 面板会永远被夹到左边距，断言「在视口内」会**假通过**。故 `place(panel, {x,y})`
> 显式接受坐标，这样「越界翻左」才真正可观测。
> 实测：光标 1200、视口 1280 → 面板落在 884（左侧）。

### 物价系统（2026-10-13 重建）

**旧系统的断层**：卡价在「个位数~几十」，收集品在「百~万」，差 1~3 个数量级
→ 打一场买不起一张牌，捡一个白收集品能买 50 张牌 → 卡牌经济形同虚设。

**新标度**（与战斗收入对齐）：

```
一场普通战 6~10   一场精英战 22~30   一次撤离 ≈ 110~240 + 收集品
基础元素(深1) 12   钢铁(深3) 165   堡垒(深4) 255   元素王(深5) 311
```

**定价公式**：

```
直购价 = 12 × (WV/5)^0.85 × depth^0.95
合成价 = Σ(材料价) × (1.10 + 0.06 × 材料数)
最终价 = max(直购价, 合成价)        ← 保证合成不比买材料更亏
```

**深度语义**（定价主轴，性价比必须随深度递减）：

| 深度 | 含义 |
| ---: | --- |
| 1 | 基础资源（可购买/掉落） |
| 2 | 复合产物（气=水+火、元素人=共鸣+元素） |
| 3 | 深链（钢铁=砂+火+增幅、大元素=元素人×2+共鸣） |
| 4+ | 终端（火枪、堡垒、元素王） |

> ⚠ `钢铁` 在卡表中编为「011 元素」，但原文称其「经过冶炼」，故深度显式设为 **3**。
> 元素之间有合成环（水←冰+气，冰←水+冷却），递归推断有歧义，故关键牌用
> `DEPTH_OVERRIDE` 显式指定。

### 卡牌是可交易资产

带出的卡**既能自用也能在市场卖出**——这是「跑刀」除收集品外的第二种变现路径。

- 运行时价表：`html-demo/js/card-prices.js`（由 `html-demo/tools/gen_price_table.cjs` 生成，`npm run prices`）

> ⚠ 生成器是 **`.cjs`** 不是 `.js`：仓库 `package.json` 有 `"type": "module"`，
> `.js` 会被当作 ESM 从而破坏其 `module.exports`。改名后别忘了同步所有引用。
- `economy.js` 暴露 `setCardPriceTable` / `cardPriceOf` / `cardSellReference`
- 市场售价参考 = 权威价 × **85%**，恒低于买价 ⇒ **无无风险套利**（已验证 0 例外）
- 市场货架：12 种常驻基础牌（×10）+ 8 种进阶牌（×3），价格全部读权威表

> ⚠ **必须共用一份价表**：否则会出现「合成 165、市场卖 12」的套利漏洞。

## 自由市场（玩家可操控 + 系统保底）

设计意图：**玩家可操控的自由市场，通过系统补货维持基本平衡；自由市场本身是乐趣之一。**

### 弹性补货（`applyElasticRestock`）

| 参数 | 值 | 作用 |
| --- | ---: | --- |
| `SYS_BASE_QTY` | 12 | 系统基准库存，**补到即停**（不无限灌货） |
| `SYS_RESTOCK_PER_TICK` | 3 | 单个商品每次补货上限 |
| `SYS_RESTOCK_INTERVAL_MS` | 30000 | 补货节拍（**真实时间**，每 30 秒一批） |
| `SYS_ITEM_CAP_PER_TICK` | 48 | 单次最多触及的商品数（须 ≥ 目录条目数） |
| `SYS_HARD_FLOOR` | 2 | 绝对下限，低于此值**无视玩家抑制**必须补 → 任何商品不会永久断供 |

**让位于玩家**：同 `catalogId` 有玩家挂牌时，系统在硬下限之上的补货被抑制。
实测：无玩家 → 0→3；玩家挂 10 件 → 只到 2（硬下限）；玩家挂 50 件 → 仍到 2。

#### ⚠ 三个曾经踩过的坑（2026-10-13 修「市场为空」）

1. **补货不能按「天」**。原实现用 `lastRestockDayKey !== today` 作闸门，
   **一天只补一次**——玩家把库存买光后当天市场永远为空。
   现改为真实时间节拍（30s），买光后约 30 秒恢复（实测 3 个节拍 99→297 件）。
2. **`SYS_ITEM_CAP_PER_TICK` 从列表头部起算会让尾部商品永久饿死**——
   装备与收集品库存一直是 0。现按「**缺货最严重优先**」排序，且上限高于目录条目数。
3. **收集品不能用随机 uid 作 `catalogId`**——目录自愈会把它们当「缺失」反复追加，
   `listings` 无限增长（29→33→37→41）。现用稳定身份 `collect-<稀有度>#<序号>`。

#### 目录自愈（`reconcileCatalog`）

每次读取都会核对「该有的系统商品」，缺什么补什么。这修掉两类问题：

- 旧存档看不到后来**新增的卡牌**（`migrateState` 只迁移字段）
- `listings: []` 是**合法数组**，不算损坏 ⇒ 空目录无法自愈

#### 测试便利入口（浏览器控制台）

```js
FBMarketDev.status()   // 系统条目 / 售罄数 / 下次补货时间 / 剩余秒
FBMarketDev.refill()   // 立刻把市场补满
FBMarketDev.sellOut()  // 清空系统货源（验证补货恢复）
FBMarketDev.wipe()     // 删除市场存档，下次进入全新播种
```

> 市场版本已升至 **v3**（`lastRestockAt` 时间戳）。旧 v2 存档首次进入会
> 自动迁移并补入缺失商品，届时会弹一次「市场已补入 N 项新货源」。

### 控盘玩法闭环

```
部分买入扫货 → 系统库存见底 → supplyState().playerCanPriceUp = true
→ 高于参考价挂出 → 赚差价
```

`supplyState(state, zone, catalogId)` 返回 `systemQty / playerQty /
playerCanPriceUp / crowded`，市场详情页据此提示「可以高于参考价」或「需低于参考价」。

### 两条硬规则

1. **手续费保底 1 代币**。低价值商品若用 `floor(价 × 5%)`，12 代币的卡手续费为 0
   → 卖价 = 买价 → 市场零摩擦、可无限无风险套利。
2. **允许自购，但只扣手续费**。自购是控盘的必要手段（单机下否则无法演示）；
   记账上物品只是回到自己手上，故全额退回、仅消耗手续费。否则自购会被重复扣款。

> ⚠ 市场卡牌价格必须读 `card-prices.js` 的权威表。若市场自行定价，会出现
> 「合成 165、市场卖 12」的套利漏洞，经济会立刻崩坏。

### 玩家标记 = 像素国际象棋棋子（`js/pieces.js`）

**每个角色对应一枚不同的棋子**，8×8 位图手工绘制在源码里：

| 角色 | 棋子 | 主题色 | 依据 |
| --- | --- | --- | --- |
| `pure` 纯白 | 主教 Bishop | 雪白 `#dfe9ff` | 雪与留白 |
| `royalty` 王权 | 国王 King | 琥珀金 `#ffb84d` | 交易与条件的行家 |
| `rock` 磐石 | 城堡 Rook | 岩灰蓝 `#8fa6c4` | 沉稳如岩 |
| `hero` 豪杰 | 骑士 Knight | 刀锋红 `#ff5a6a` | 刀与胆色 |

**渲染方式**：位图 → SVG（每段连续像素一个 `<rect>`）→ `mask-image`，颜色由 CSS 变量提供。

> ⚠ **不要改回 `clip-path: polygon()`**。一枚棋子里可能有**互不连通**的矩形段
> （城堡的两个垛口在同一行是两段），polygon 的 nonzero 填充会让它们互相抵消 →
> 整枚棋子渲染失败。SVG 的多个 `<rect>` 没有这个问题，且同样保持硬边像素观感。

> ⚠ SVG 用 `encodeURIComponent` 完整编码，**不要**改成手工替换 `#` 与尖括号——
> 部分解析器会因为逗号/引号而失败。

- 无图片资源，任意缩放不糊（`image-rendering: pixelated`）
- 未知角色回落为国王，不会渲染空白
- `applyTo()` 幂等，重复进入不会重复注入样式
- 无 `pieces.js` 时地图回落到硬边像素三角（不再是圆角胶囊）

### 地图地形（确定性噪声）

五种异星地表 `plain / moss / crystal / basalt / crater`，由两层值噪声（尺度 4.5 与 2.2）
加 8% 高频抖动生成，**成片分布**而非随机噪点。

- 实测分布：平原 30.6% / 玄武岩 25.6% / 陨坑 18.8% / 晶簇 14.5% / 苔原 10.5%
- 相邻同地形比例 **48.2%**（纯随机约 20%）→ 读起来像地貌而非雪花屏
- **确定性**：同一 `(x,y)` 每次结果相同，存档/刷新后地图不变
- 纯装饰，不影响玩法；迷雾下不显示纹理，避免泄露地形信息

> ⚠ 抖动权重不要调高（会破坏成片性），也不要只用两层噪声——
> 两层加权和最大只有 0.7，`crystal` 档（阈值 0.8）会**一个格子都生成不出来**。

### 4.2 ✅ 已澄清（原判断有误）：ENC-01「四个野人」

**先前的错误判断**：把它当成"静态 DPS 求和"（4 单位全程输出 ≈34 伤/5s，玩家仅撑 9s），
据此认为它"近乎必死"、并建议引入"组行动预算"。

**用户指正后的正确理解**：这场遭遇是**动态级联 + 阈值解谜**，机制有三层：

1. **减员级联**——每杀一个单位，敌方每 5s 的行动数就少一次。
2. **阈值设计**——单位血量（冠军13 / 野人16 / 射手19 / 酋长25）卡在"一击能否击杀"的分界上。
3. **酋长白板**——`skipIfAlliesAlive`：友军存活时它不攻击。

**实测可达性**（focus fire + 最优击杀顺序，玩家 60 HP）：

| 单窗口伤害 | 一击可杀 | 最优顺序 | 酋长行动 | 结果 |
|---:|---:|---|---:|---|
| 5（1费基础） | 0/4 | 野人→冠军→射手→酋长 | 1 | ❌ 承伤 79 |
| **12（旧2费，现已废弃）** | **0/4** | 野人→冠军→射手→酋长 | 2 | ❌ 承伤 71 |
| **14（现行 2 费）** | **1/4** | 冠军→野人→酋长→射手 | 1 | ✅ 剩 17 |
| 21（旧3费，现已废弃） | 3/4 | 冠军→酋长→野人→射手 | 0 | ✅ 剩 37 |
| **27（现行 3 费）** | **4/4** | 冠军→酋长→野人→射手 | 0 | ✅ 剩 39 |

**关键结论：ENC-01 是构筑门槛检查点，不是必死局。**
基础牌与 2 费构筑过不去，3 费（27 伤）可清场并剩 39 HP。
**它是"该去合成了"的信号**，这个设计意图是成立的。

### 7.6 每次改动的工作流（务必遵守）

```bash
npm run archive -- <标签>     # 1. 留档（用户硬性要求，可回溯）
# ...改代码...
npm run check                 # 2. 盖章 + 体检，必须全绿（50 项）
npm test                      # 3. 全量测试（151 项）
npm run balance               # 4. 平衡对比（固定种子，可跨版本比）
git add -A && git commit      # 5. 提交（信息里写清"为什么"）
```

> **`npm run check` 会先跑 `stamp.mjs`，顺序很重要**：改了 js/css 后缓存戳必须重算，
> 否则体检会报"缓存戳漂移"。这是设计上的保护，**不是误报**。

### 7.7 三条不要踩的坑（本轮实际踩过）

1. **不要用 `clip-path` 画像素棋子**——同一行两段不连通矩形会被 nonzero 填充
   **互相抵消**，整枚棋子渲染失败。用 SVG `<rect>` 作 mask。
2. **不要只用两层 valueNoise** 生成地形——加权和最大仅 0.7，
   高阈值档（晶簇，0.8）会**一个格子都生成不出来**。这个 bug 靠统计分布才发现。
3. **不要把 `gen_price_table` 改回 `.js`**——仓库 `"type":"module"` 会破坏其
   `module.exports`；改扩展名后必须同步 `package.json`（曾静默失效很久）。
